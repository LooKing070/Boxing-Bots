## 1. СУТЬ ПРОЕКТА
Полностью трёхмерный браузерный файтинг с видом сбоку (вид сбоку = позиция камеры,
см. MEC §8 CAM_*): гуманоидные роботы из кубов; процедурные повреждения без HP-баров
(уменьшение кубов скелета, отсечение конечностей, дебаффы); PvE и PvP 1v1 (P2P с хостом);
4 сцены; десктоп + мобильные, только landscape. Правила — MECHANICS, вид — STYLE,
экраны — SCENES, код — ARCHITECTURE, мультиплеер — NETWORK.

## 2. СТЕК
| Компонент | Технология | Обоснование |
|---|---|---|
| Рендер | Three.js ≥0.164 (WebGL 2) | процедурная геометрия; InstancedMesh = тысячи кубов одним draw call |
| Физика | Rapier.js ≥0.12 (WASM) | Rust→WASM; Convex Decomposition для обломков; лёгок для мобильных |
| Лобби | Colyseus ≥0.15 | подбор соперника/метаданные; НЕ симулирует бой |
| Бой | PeerJS / WebRTC | P2P с хостом по требованию заказчика |
| Неткод | Prediction + Reconciliation (rollback ≤ ROLLBACK_MAX_FRAMES) | отзывчивость файтинга |
| UI | Lit ≥3.1 + Zustand ≥4.5 | минимальный бандл, Web Components поверх канваса |
| Сборка | Vite ≥5.2 | HMR, WASM/GLSL-плагины |
| Язык | TypeScript ≥5.4 strict | общие контракты client/server |
| Пакеты | pnpm ≥9 workspaces | монорепозиторий |
| Звук | Howler.js ≥2.2 | Web Audio, обход автоплея Safari/iOS |
| Ввод | Pointer Events API | мышь+тач, multi-touch по pointerId |

## 10. DEFINITION OF DONE И ПРИЁМКА
QA-DOD (итог, всё обязательно):
1. Запуск на десктопе и мобильном; адаптивный UI; тач-управление.
2. Все 4 сцены реализованы и связаны навигацией.
3. Повреждения всех уровней: обшивка, скелет (уменьшение), компоненты (пороги 60%/0%).
4. Разрушения видны на модели; HP-баров нет (урон — цифрами).
5. Надписи о повреждении компонентов — 2 сек.
6. Отсечение конечностей работает; внутренности не отваливаются; обломки — мусор без урона.
7. Дебаффы: задержка 0.5 с; −30% силы; −40%/−50% скорости; виньетка.
8. Редактор создаёт удары и блоки, привязка к A–D; пресеты сохраняются.
9. Блок: стамина (тап −10, −10/с, +2/2 с); визуал — только поза и полоска над ботом.
10. «Укрепление» −35%; «Контрудар» 8% в случайный кубик бьющей руки атакующего.
11. Победа: нокаут (материнка/аккумулятор) или больший суммарный урон за 180 с.
12. Кнопки: A–D справа снизу, движение слева снизу; safe-area учтён.
13. PvP P2P: хост авторитетен; дисконнект хоста — отмена; гостя — 10 с и победа хоста.
14. Звуков шагов нет; звуки по материалу; ≤3 одновременных.
15. Лимиты: ≤1000 кубов/бот; ≤300 физ. тел; частицы 150/50.
16. FPS ≥30 мобильные / ≥60 десктоп; бандл ≤ BUNDLE_GZIP_MB.

Чек-листы фаз (приёмка агентом самопроверкой):
Фаза 1: бот генерируется ≤ BOT_CUBE_LIMIT (юнит-тест); ходит/прыгает; камера следует; арена и свет по STYLE §5.
Фаза 2: тесты MEC-2 (пороги), MEC-3 (отсечение локтя/бедра/шеи), дебаффы 7 видов состояний; пулы в лимитах.
Фаза 3: редактор сохраняет 4 пресета; стамина по формуле; контрудар бьёт в руку атакующего (тест); PvE дерётся.
Фаза 4: все SCN-чек-листы (кнопки, safe-area, multi-touch, оверлеи); звуки по таблице STYLE §6.
Фаза 5: PvP-матч на 2 клиентах; сценарии дисконнектов NET-6; rollback-тест с искусственным лагом 150 мс.
Фаза 6: профилирование по MECHANICS §9 на целевых устройствах; кросс-браузерная матрица.
